## Executive Summary

Agent memory benchmarking has a measurement-validity crisis: when an end-to-end agent scores well on a long-horizon recall task, nobody can say whether the credit belongs to the memory system, the embedding model, the retrieval pipeline, or the generation model reading a large context window. The confound is not hypothetical. The MemDelta study (arXiv:2606.29914) showed that swapping only the embedding model in an otherwise identical memory pipeline shifted accuracy by 6.2 percentage points and reversed which system ranked higher, and vendor self-reported scores are chronically contested — Zep's LoCoMo number has appeared publicly as roughly 84%, a revised 75.14%, and 58.44% in a competitor's reproduction, three figures for the same system.

The Agent Memory Leaderboard (AML, agentmemories.ai), launched July 29, 2026 by a 20-plus-institution academic consortium with first results landing mid-August, is the most institutionalized response so far: contestants implement exactly two HTTP verbs, Add and Search, while the platform locks the answer model, prompts, evaluators, dataset suite, top-k, and aggregation. Any LLM used inside the submitted memory system is pinned to gpt-4o-mini, and the platform reserves the right to reproduce a submission and invalidate results that diverge materially. This is mechanism-level evaluation: the leaderboard measures the retrieval surface of a memory system and deliberately nothing else.

The design buys real rigor at a structural price. An Add/Search contract fits vector-store and graph-store memory products cleanly, but has no natural slot for architectures where the agent itself curates memory as readable files — a paradigm one systems paper (arXiv:2606.24775) argues existing evaluations structurally cannot represent, and which Letta's own experiment inadvertently supported when a bare filesystem-tool agent beat a purpose-built graph memory on LoCoMo (74.0% vs 68.5%). Accuracy-only leaderboards also ignore latency and cost entirely, and adjacent-leaderboard history (LMArena's "Leaderboard Illusion," MemPalace's 48-hour score retraction) shows exactly how competitive stakes reshape what gets optimized. Mechanism-level scores are a meaningful floor for comparing pluggable memory backends; they are not a verdict on what makes production agents work.

## The Isolation Problem: Why End-to-End Memory Scores Mislead

Three findings establish that the generation-model confound is real and large:

- **MemDelta (arXiv:2606.29914)** is the most direct controlled treatment. Its framing: "reported gains often mix changes in the memory method with changes in the language model, embedding model, or retrieval pipeline, making it unclear what is actually being measured." Beyond the 6.2pp embedding-swap swing, it found ranking flips across model families (one model gained 14pp from full-context reading while another gained 31pp from RAG on the same tasks), and that once cost was controlled, one celebrated memory framework merely matched cloud RAG at roughly 50x the cost.
- **Vendor reproduction wars.** Mem0's LoCoMo score appears as 92.5 on its own site, 66.9 in its own ECAI paper (arXiv:2504.19413), and 68.5 in a third-party reproduction. Zep's public dispute with Mem0 over reproduction methodology (including an allegation that a latency comparison ran Zep sequentially where parallel search was available) illustrates that even good-faith vendor benchmarking degenerates without a neutral referee.
- **Prior art in adjacent fields.** RAG evaluation methodology long ago split retriever-only, generator-only, and end-to-end scoring to avoid exactly this misattribution, and MTEB exists so embedding models can be compared on a shared surface. Memory evaluation is arriving late to a lesson retrieval research already institutionalized.

A second leaderboard, Agent Memory Benchmark (AMB, agentmemorybenchmark.ai, Vectorize/Hindsight, March 2026), targets the overlapping problem from a different angle and predates AML by four months — its manifesto argues that million-token context windows have turned recall benchmarks into tests of "whether your LLM can read." The two efforts are independently organized and easily confused; the existence of two competing referees within five months is itself evidence of how acute the measurement problem has become.

## The Add/Search Contract and What Plugs Into It

AML's interface is the minimal common denominator of the pluggable-memory field. Add ingests conversation messages scoped by user and session; Search takes a query and returns ranked memory evidence; the platform's fixed generation model composes answers only from what Search returns. Submissions bind to a commit or image version, and the two tracks differ in verification burden: academic/open-source entries must supply a public verifiable repo, commercial entries must keep a stable API reachable for 30 days.

The six major frameworks all expose an Add/Search-shaped surface while diverging completely underneath: Mem0 runs LLM-based fact extraction with a conflict-resolution stage over a vector store; MemOS unifies plaintext, activation, and parametric memory behind a MemCube abstraction; Zep/Graphiti maintains a bi-temporal knowledge graph that tracks both when facts became true and when they were superseded; Letta/MemGPT has the agent itself edit a three-tier memory via tool calls; LangMem ships hot-path memory tools over a pluggable store without its own storage engine; Cognee runs an add → cognify → memify → search pipeline over hybrid vector-graph-relational storage. Notably, no formal cross-vendor interface standard exists — nothing analogous to a shared retriever abstraction — so each harness integration remains bespoke, and AML's contract is in effect a de facto standardization proposal delivered as a benchmark.

The pinned internal model deserves emphasis as a design choice. Memory systems routinely use an LLM for extraction, summarization, and conflict resolution at ingest time; letting each contestant choose that model would reintroduce the confound one layer down. Pinning it to gpt-4o-mini makes ingestion intelligence a controlled variable — at the cost that any system whose memory curation depends on a stronger model must ship a degraded port of itself to compete.

## The Dataset Substrate Is Weaker Than the Harness

Mechanism-level rigor at the harness layer cannot repair label-quality problems in the datasets underneath:

- **LoCoMo** (1,540 QA pairs over 10 long conversations) — an independent audit found a 6.4% label-error rate, and its gpt-4o-mini judge accepted wrong-but-topically-adjacent answers 62.8% of the time, capping the meaningful score ceiling near 93.6%. A successor (Locomo-Plus) exists specifically to fix these flaws.
- **LongMemEval** (500 questions; the -S variant runs ~115K tokens across 30-48 sessions) covers extraction, multi-session reasoning, temporal reasoning, knowledge updates, and abstention — the closest public coverage of memory governance. Commercial assistants drop ~30% accuracy on it versus short-context settings.
- **PersonaMem** stresses preference tracking over up to 60 sessions; the best models reach only ~52%, and reasoning-optimized models show no advantage — evidence it measures tracking, not reasoning depth.
- **BEAM** scales to 10M tokens, where third parties note scores may increasingly reflect raw context capacity rather than memory architecture; **CLBench** is an in-context rule-learning benchmark whose inclusion in memory suites is a scope stretch; **ScriptMem** carries an explicit conflict-of-interest flag — its co-creator MemoraX tops both its own benchmark and, currently, the AML commercial leaderboard (58.02, with MemOS at 45.89 and Mem0 at 41.40).

That last pattern — a benchmark co-author leading the leaderboard that incorporates its benchmark — is not evidence of wrongdoing, but it is exactly the situation blind test sets and reproduction rights exist to police.

## Anti-Gaming Design, Learned From Other Leaderboards' Scars

AML's defenses read like a checklist compiled from adjacent leaderboards' failures: fully blind gold data (the repo publishes evaluation contracts but explicitly excludes corpora, held-out questions, gold answers, and rubrics), version-bound submissions, platform-side reproduction with invalidation rights, a no-withdrawal rule once a full evaluation is accepted, and a cross-contamination ban on sharing memories across user IDs or teams.

The scars it is responding to are well documented. Kaggle normalized public/private splits because iterative overfitting to visible feedback is otherwise guaranteed. SWE-bench Verified accumulated contamination concerns and, per OpenAI's 2026 statement, stopped meaningfully differentiating frontier models. LMArena's "Leaderboard Illusion" analysis (NeurIPS 2025) documented private pre-release variant testing, asymmetric battle allocation, and silent model removals — and separately showed that fine-tuning on Arena-style prompts yielded a 112% ArenaHard win-rate gain with no general-capability improvement, the textbook Goodhart outcome. Within memory benchmarking itself, MemPalace launched claiming 96.6% on LongMemEval and retracted within 48 hours after acknowledging the headline applied to an unrepresentative configuration.

One methodological caveat on AML's current standings: all visible leaderboard entries share a single submission timestamp with bulk-import user IDs, suggesting the launch snapshot is a batch evaluation rather than a live rolling competition. And a genuine reporting gap: AML's lettered capability categories (A-H in the leaderboard JSON) have no published mapping to its seven-dimension README taxonomy. One category scores dramatically below all others across nearly every system (the leader manages ~30 where its strong dimensions run 76-93; the runner-up scores under 10) — but whether that weakest dimension is rule/process execution or epistemic safety and privacy depends on an unpublished letter-to-name mapping, and honest reporting requires flagging that ambiguity rather than asserting either reading.

## What Mechanism-Level Scores Do Not Measure

Three limits matter for anyone consuming these numbers:

**Architecture fit.** The Add/Search paradigm presumes memory is a separable subsystem a harness can call. Agent-managed memory — where the agent reads, writes, and reorganizes its own memory as plain files, and the "system" is inseparable from the agent's judgment about what to record — has no natural plug point. The June 2026 systems paper (arXiv:2606.24775) makes the structural argument: evaluations that treat memory as a monolithic black box cannot represent architectures whose effectiveness depends on workload alignment, and "no single architecture dominates across all scenarios." Letta's filesystem-agent result is the empirical hint in the same direction. A team running file-based agent memory can port its distillation logic into an Add/Search adapter for scoring purposes, but the score then describes the port, not the architecture.

**Operational reality.** Accuracy-only leaderboards are silent on latency, cost, and write-path overhead — dimensions where the field's numbers are stark: reported production tolerances range from minutes-long latencies to none specified at all, most production teams reportedly bypass public benchmarks in favor of A/B testing, and caching-layer engineering (semantic caching cutting query time from 110ms to sub-millisecond; plan caching halving cost) moves production outcomes in ways no recall score captures. The one controlled study of memory in coding agents found memory improved efficiency on complex tasks (22-32% cost savings, 28-40% fewer turns) while leaving code-quality scores flat and acting as pure overhead on simple tasks — the production-relevant metric was not the one recall benchmarks measure.

**Field-shaping incentives.** A leaderboard this legible will attract optimization pressure toward its specific dimensions and its pinned model's ingestion quirks. That is not a flaw unique to AML — it is what leaderboards do — but it means the field's memory architectures will drift toward what Add/Search-plus-gpt-4o-mini rewards, and paradigms outside that contract will need their own evaluation story or risk looking unmeasurable rather than different.

## Practical Takeaways

- Treat mechanism-level leaderboard scores as comparing retrieval surfaces under a controlled harness — a genuine improvement over vendor self-reporting, whose contested-reproduction record (three public numbers for one system) justifies the referee's existence.
- Before consuming any memory benchmark number, ask three questions: who controlled the generation model, who has seen the gold data, and who reproduced the run. AML's answers (platform, nobody, platform) are the strongest currently on offer.
- Do not read absence from — or mediocrity on — an Add/Search leaderboard as evidence against agent-curated memory architectures; the contract structurally cannot host them, and the strongest current critique of the paradigm comes from exactly that mismatch.
- Watch the dataset layer, not just the harness: a blind, reproduced evaluation over labels with a 6.4% error rate and a lenient LLM judge still inherits those defects.
- For production decisions, pair any accuracy leaderboard with cost, latency, and task-efficiency measurements; the one controlled coding-agent study found memory's real production value showed up in efficiency, a dimension recall benchmarks do not score.
