title: Managing Components
description: Install, upgrade, and remove Zylos components.
---

The `zylos` CLI handles component lifecycle management. You can also ask Zylos directly through any connected channel -- it will run the CLI commands and guide you through configuration.

## Installing a Component

### Through Zylos (Recommended)

Just tell Zylos what you want:

```
Add the Telegram component
```

Zylos will:
1. Run `zylos add telegram`
2. Ask for any required credentials (e.g., Bot Token)
3. Save credentials to `~/zylos/.env`
4. Configure the component
5. Start the PM2 service

### Through the CLI

```bash
zylos add <component-name>
```

After the CLI finishes downloading, Zylos handles the rest -- configuration, service setup, and verification.

## Upgrading a Component

### Check for updates

```bash
# Check a specific component for updates (downloads to temp for comparison)
zylos upgrade <component-name> --check

# Upgrade a specific component
zylos upgrade <component-name>

# Upgrade all components at once
zylos upgrade --all
```

The upgrade process:
1. Backs up the current version
2. Downloads the new version
3. Preserves your configuration (`config.json`, `data/`)
4. Restarts the PM2 service

### Upgrading Zylos Core

```bash
zylos upgrade --self
```

This upgrades the core framework itself (the `zylos` CLI and built-in components).

## Uninstalling a Component

```bash
# Remove the component (keeps data directory by default)
zylos uninstall <component-name>

# Remove the component and its data directory
zylos uninstall <component-name> --purge
```

By default, `zylos uninstall` removes the component's source code and PM2 service but keeps the data directory (`config.json`, logs). Use the `--purge` flag to also delete all data.

## Component Directory Structure

Each component has two directories -- one for source code (managed by the CLI) and one for runtime data (your configuration and logs):

```
~/zylos/components/telegram/   # Runtime data
  config.json                  # Runtime configuration
  logs/                        # Component logs
  media/                       # Downloaded media (if applicable)
```

Source code and service definitions live in the skill directory, managed automatically during install and upgrade. You generally don't need to interact with source files directly.

Secrets (API keys, tokens) are stored in the global `~/zylos/.env` file, not in component directories.

## Viewing Component Info

```bash
# List installed components with versions
zylos list

# Check service health
zylos status

# View PM2 service logs
pm2 logs zylos-<component-name> --lines 50
```
