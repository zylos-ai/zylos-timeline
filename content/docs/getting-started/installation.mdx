Zylos ships with an automated installer that handles the entire setup process. You'll go from zero to a running instance in about five minutes.

## Quick Install

Run the following command on your server:

```bash
curl -fsSL https://raw.githubusercontent.com/zylos-ai/zylos-core/main/scripts/install.sh | bash
```

The installer will:

1. Install the `zylos` CLI as a global npm package (`npm install -g zylos`)
2. Install and configure PM2 (process manager)
3. Create the directory structure under `~/zylos/`
4. Set up the Claude Code CLI
5. Generate default configuration files

## Interactive Setup

After the installer finishes, run the initialization wizard:

```bash
zylos init
```

You'll be prompted for:

- **Authentication** -- Either an Anthropic API key or a Claude Max setup token. Both are stored locally in `~/zylos/.env` and never leave your machine. You can also provide these via environment variables (`ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN`).
- **Domain name** (optional) -- If you want to access the web console over HTTPS, enter your domain. Caddy will automatically provision SSL certificates. Otherwise, skip this and use localhost.
- **Timezone** -- Your preferred timezone (e.g., `Asia/Shanghai`, `America/New_York`).

The wizard also installs and configures Caddy (the HTTP server), sets up PM2 services, and generates a web console password.

**Non-interactive mode** is available for automated deployments:

```bash
zylos init --yes --api-key sk-ant-... --domain example.com --timezone UTC
```

Run `zylos init --help` for all available options.

## Verify the Installation

Run the built-in health check:

```bash
zylos doctor
```

This command verifies:

- Node.js version meets requirements
- PM2 is running and managing Zylos services
- API key is valid and can reach Anthropic
- All core components are present
- Memory system is initialized

A healthy installation will show all checks passing in green. If anything fails, the output will include specific remediation steps.

## Directory Structure

After installation, your Zylos home looks like this:

```
~/zylos/
  .env                # API keys and settings (never commit this)
  .zylos/             # Core framework files and component registry
  .claude/            # Claude Code configuration and skills
    skills/           # Skill source code (managed by zylos CLI)
  components/         # Runtime data for installed components
  memory/             # Persistent memory files
    identity.md       # Bot personality and principles
    state.md          # Current active work
    references.md     # Pointers to key resources
    users/            # Per-user profiles
    reference/        # Decisions, projects, preferences
    sessions/         # Session logs
  activity-monitor/   # C2 status files and logs
  comm-bridge/        # C4 message database and attachments
  scheduler/          # C5 task database
  http/               # Caddy config and public files
  pm2/                # PM2 ecosystem configuration
  workspace/          # Working area for repos and experiments
  logs/               # System logs
```

## What's Next

Your Zylos instance is running, but it can't talk to anyone yet. The next step is connecting a communication channel so you can start interacting with it:

- [Telegram](/docs/channels/telegram) -- The most popular channel for personal use (5 min setup)
- [Web Console](/docs/channels/web-console) -- Built-in browser interface, no external accounts needed
- [Lark / Feishu](/docs/channels/lark) -- Great for teams and enterprise use

You can also interact with Zylos directly through the Claude Code CLI on your server.
